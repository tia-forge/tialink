# 用 agent 做批量复制：可直接粘的提示词

给已经接上 TiaLink MCP 的客户端（Claude Code / Cursor / VS Code 等），把下面整段连同点表一起贴进去。
**适用规模：≤10 台。** 再多就别让模型逐块改 XML 了，用 `tialink-batch.mjs`，提示词改成"跑这个命令并把输出解释给我"。

---

## 提示词

```text
背景：这台机器上装着 TiaLink（默认 http://localhost:8080），博途里开着一个工程，
里面有一个已经调好的模板功能块 FB_MotorSeq（3 个 Bool 输入、1 个 Time 输入、2 个 Bool 输出）。

任务：把 FB_MotorSeq 批量复制成 4 台同类设备，块名 FB_<name>，背景 DB 名 DB_<name>。
每台的差异见点表（CSV，列名 = 接口成员名，Bool 列是地址，其它列是字面值）：

no,name,Start,StopPermit,Fault,RunDelay,Motor1,Motor2
1,Valve01,%I30.0,%I30.1,%I30.2,T#4S,%Q30.0,%Q30.1
2,Valve02,%I30.3,%I30.4,%I30.5,T#6S,%Q30.2,%Q30.3
3,Valve03,%I31.0,%I31.1,%I31.2,T#8S,%Q31.0,%Q31.1
4,Valve04,%I31.4,%I31.5,%I31.6,T#10S,%Q31.2,%Q31.3

约束（按顺序执行，任一条做不到就停下来问，不要猜）：
1. 先只读：报出当前工程的设备、模板块的接口成员，确认点表列名与接口一一对应；
   对不上就停下来说明哪一列没用上。
2. 检查点表：地址有没有重复、块号 300 起有没有被占用。有问题先报，不要继续。
3. 预检（dry run）一次，把"将创建的对象清单"给我看。等我确认后再真写。
4. 每份副本：块名/块号/标题按台号改；Time 类输入的默认值取点表；
   注释里出现台号的地方按点表改，**改不了的地方列出来**，不要沉默地留着。
5. 背景 DB 必须指向自己那份 FB（不是模板 FB）。
6. 变量表按点表地址**原样**建，一个地址都不许自己推算。
7. 全程不要保存工程。最后给我三样：
   a) 编译结果（错误数、警告数、以及每条警告原文）
   b) 第 1 台与第 4 台的块导出 diff（哪几行不同、为什么）
   c) 你认为需要人工复核的点
```

---

## 为什么每条约束都必要

| 约束 | 对应的事实 |
|---|---|
| 第 1 条"只读 + 对列名" | 点表列名和接口对不上时，错位是静默发生的：写进去的是别的参数 |
| 第 2 条"先查重复与占用" | 地址重复不会让编译失败，只在下载后表现为两台设备抢一个点 |
| 第 3 条"预检后等确认" | 预检只回报第一个根对象，"看起来只建了一个"是汇报口径，不是事实 |
| 第 4 条"改不了要列出来" | 注释里的半结构化句子（"2 号电机在 1 号运行之后启动"）没有规则能改全 |
| 第 5 条"DB 指向自己那份 FB" | 复制实例 DB 时最容易漏的一处，编译报的却是"实例与接口不匹配" |
| 第 6 条"地址原样" | 让模型"顺手把地址排整齐"是这类任务里最危险的自作主张 |
| 第 7 条"不要保存" + 三样验收物 | 不保存 = 改错了什么都没发生；diff 报告是唯一能证明"每台的差异真的不同"的东西 |

## 什么时候该换成脚本

- 设备数超过 10～20 台：逐块改 XML 的成本按台数线性涨，脚本不变；
- 要反复重跑（今天 8 台，下个月 14 台）：重跑需要幂等，脚本本来就是幂等的；
- 要进 git / 要 review：脚本 + 点表是可 review 的文本，对话记录不是。

反过来，**一次性、探索性、需要判断的活**留给 agent：摸清接口、发现点表里的坑、判断"这台要不要单独处理"——这些是提示词擅长的，脚本不会做。
